# Core beta136 — explicit shared subscription custody

An optional, explicitly started HTTP host reuses Core's Claude/Codex protocols
for installations sharing one rotating credential store. Compatible root
inference is retained; encoded exact-account routes, bounded nonsecret inventory
and exact-account catalogs support named remote connections. Distinct management
keys retain their authority; an unkeyed endpoint requires an explicit opt-in.
The default kernel and in-memory connection start no listeners.

Offline remote catalog adoption preserves original ids, defaults, sampling and
budget groups without copying refresh tokens. Local account connection toggles,
labels and priority no longer mutate a shared credential used by another
catalog. Direct custody administration remains explicit. Subscription capabilities
make sign-in availability discoverable to authenticated hosts.

Real local HTTP qualification covers both vendors' complete and streamed calls,
exact account selection, early quota fallback through the actual native SDK,
per-account token limits, credential and administrative isolation, disabled
accounts, exact catalog identity and lifespan cleanup. Full installed-cohort
qualification and live remote acceptance remain separate gates.
