# Core beta149

Concurrent journal appends no longer leave a pending write result that can make
an unrelated state save fail its commit. The shared SQLite path consumes
`RETURNING` rows in one worker operation, including orphan task-run updates and
in-memory operational history revision allocation.
Public results, privacy checks and storage recovery policies remain unchanged.

Provider fallback now preserves the runner's conversation message list, including
the backup's answers and executed tools. Request repairs retain generated
messages without replacing original input, and stop fallback after committed
tools. History readers also recover recorded text from older completed user-only
fallback envelopes, without rewriting stored runs or inventing tool evidence.

See the [storage concurrency contract](../sqlite-commit-concurrency.md).
See the [fallback conversation history contract](../fallback-conversation-history.md).
Real SQLite regressions cover concurrent writes and retained journal/state data.
Installed qualification, public artifacts and live host acceptance are separate
release gates.
