# Embedding beta 184

Some providers send a successful HTTP response and report an error in the
first server-sent event. The OpenAI-compatible streaming adapter now reads the
structured error status. A 401 received before the first provider output frame
lets a configured account group try an eligible account for the same model.
The synchronous and asynchronous paths follow the same rule. If an error
arrives after any output frame, the stream ends and keeps the partial response.
The router does not replay it.

Beta 182 relays could send `subscription_refused` alone for a 403, 409 or 422.
The account router reports that event as 400 without trying a sibling account.
The distinct `subscription_account_not_connected` code still means 409. New
relay events carry the explicit status. An HTTP 4xx or 5xx response takes
precedence over the status in a public subscription error body.

See the [account routing guide](../provider-accounts-and-backups.md) and the
[subscription relay error contract](../subscriptions.md#hosts-with-central-credential-custody).
