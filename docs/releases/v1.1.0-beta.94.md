# Core 1.1.0 beta94

Session retention no longer deletes interactive conversations.

- The scheduler run-log step of `session_retention` deleted every legacy
  `sessions` row with `session_type='agent'` idle for a day or larger than
  500 KB. On 1.1 interactive conversations carry such a row, so the step
  tombstoned users' conversations (and later their messages) within a day.
  It now matches only `scheduler:*` and `automation:*` ids; conversations are
  bounded by `retention.days` alone.
- Run-logs of scheduled runs and automations are kept for the new
  `retention.scheduler_days` (default 7), and an oversized one is trimmed to its
  newest run instead of being deleted. See `docs/session-retention.md`.
- Includes the default-router invariant (one usable classifier row, enforced by
  triggers and repaired on open) and clearer errors for empty accounts and
  oversized requests.
