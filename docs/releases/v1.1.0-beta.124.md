# Core 1.1.0 beta124

Selected staged operations can continue after timeout or runtime interruption
under an explicit durable host grant, without another user message. Core owns
the runner and scheduling; the host supplies identity, domain authorization and
idempotent fixed-expiry grant capture. Ordinary chat keeps its existing lifecycle.

- Atomic logical-origin admission, bounded segments, fresh grant validation,
  whole-operation cancellation and terminal events, including restart recovery
  before the first checkpoint.
- Explicit legacy checkpoint handoff preserves receipts and original domain
  idempotency keys. A single-source claim blocks competing legacy resumes,
  including after a crash before the handoff's first checkpoint.
- `OperationPending` distinguishes read-only readiness from generic provider
  failure and uncertain effects, with a persisted bounded retry delay.
- Public gateway and Python/TypeScript SDK provenance links physical segments
  to their logical origin. Receipt waits may use up to three hours with bounded
  polling; ordinary one-hour wait fingerprints remain unchanged.

See [the host contract](../durable-operations.md). The kernel, SQLite adapter,
gateway and Python SDK are `1.1.0b124`; independently versioned optional modules
retain their versions and are included in the immutable release manifest.

The pre-release source candidate `5d675da7242fd1d69d7a4c388a944387e9f1fbc8`
passed clean-wheel installed qualification: 1,121 tests, two skips and 188
subtests, plus the locked TypeScript SDK build/unit test and dependency check.
The official release workflow separately qualifies the exact tagged cohort and
native permission contracts on Linux, macOS and Windows before publication.
Neither fixture qualification establishes live provider or consumer acceptance.
