# Core beta140 — bounded fresh operational ACL checks

The public `resources_are_visible` reader checks operational resource ACLs in
bounded batches after fetching rows. It preserves the scalar reader's typed
principals, tenants, ownership, visibility, permissions, exact ACL versions,
input order and duplicate rows. No authorization result is cached; external
host policy, epochs and expiry checks remain mandatory.

A neutral 50,000-resource history fixture with explicit grants measured
15,125 ms before and 593 ms with the real fresh batch reader, **25.5×**.
Snapshot SQL reads dropped from 250,001 to 251. The owner-only path stayed
approximately unchanged (183 to 185 ms). Resource IDs, ordering and page data
matched; page readers retained their separate fresh checks and cursor rules.
These are controlled handler/storage measurements, not remote client timings.

Fifteen API tests with thirteen subtests cover scalar parity, types, tenants,
permissions, revocation after fetching, separate writers, version changes,
opaque IDs, bounded parameter counts, cancellation, errors and caller-owned
transactions. Host-policy denial remains separate from a successful database
ACL decision. Publication and installed-host acceptance are separate gates.
