# Core 1.1.0 beta82

Session reset no longer blocks the event loop while waiting on its synchronous
SQLite session store. Storage failures propagate instead of being swallowed by
the team router or dispatcher. The preceding deferred-tool provider-call
provenance fix is also included, preserving navigable child session links.

See [session history](../session-history.md#reset-under-sqlite-contention-beta82)
for the contention regression. Installed-wheel qualification and live host
acceptance remain separate from source checks.
