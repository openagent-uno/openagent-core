# Core 1.1.0 beta95

Attachments sent by a server-host agent reach the chat, and conversations
tombstoned by mistake can be restored.

- `send_file_to_user` checked the artifact the host publisher had just
  uploaded through the shared database connection. During a run that
  connection can sit inside an implicit transaction whose snapshot predates
  the upload, so a correctly linked file was refused with "The host publisher
  did not return a session-linked artifact". `session_output_reference` and
  `find_session_attachments` now read on a dedicated connection, like the
  upload.
- `restore_tombstoned_session` (operational repository) undoes a tombstone
  whose messages and tool calls were retained: it restores the real
  last-activity time, revives the activity row, queues search upserts and
  records `session.restored`. It refuses pruned payloads and legacy
  projections without their source row. See `docs/session-retention.md`.
