# Embedding beta 168

A dedicated PostgreSQL connection renews each runtime worker identity during idle periods and while run recovery is blocked. A heartbeat that waited on a lock checks expiry after acquiring that lock. Expired and missing epochs remain fenced. A fresh worker interrupts orphaned runs, classifies uncertain effects and preserves existing receipts under their original authority.

Embedding gateways can enable worker-specific readiness and liveness with `worker_health=True`. Readiness drains traffic on inconclusive database observations. Liveness distinguishes transient database unavailability from confirmed loss of this worker. A deferred submission that lost its epoch before admission checks for an authorized existing receipt before returning a retryable result. [Storage and health contract](../postgres-runtime.md)
