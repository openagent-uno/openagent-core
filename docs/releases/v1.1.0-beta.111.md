# Core 1.1.0 beta111

MCP stdio servers can run on demand.

- Publishes `openagent-capability-host` 1.0.0b5. `MCPStdioServer` accepts
  `idle_timeout`: after that many seconds without a call or resource read the
  ready child process is stopped while its catalog stays published, so hosts
  keep offering the tools without a running process. The next call starts the
  child again (one process for concurrent callers), repeats `initialize` and
  `tools/list`, and reports a state change only when the catalog differs. A
  running call holds the process. An idle stop is an expected exit and uses no
  restart budget; a failed on-demand start is published as unavailable and
  supervised by the ordinary bounded restart policy. `idle_stopped` reports the
  state. Without `idle_timeout` nothing changes.
- On a reference machine two Node browser and web-search MCP servers held
  about 150 MB each while idle and started again in 0.3–0.4 s including the
  catalog handshake.
