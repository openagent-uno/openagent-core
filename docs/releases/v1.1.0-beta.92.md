# Core 1.1.0 beta92

A compaction summary that times out is retried on a sibling model.

- When the summary call fails for a call-specific reason (timeout, connection,
  transient error), another enabled model of the same provider is a valid
  fallback. Before, the failed provider was always excluded, so an install with
  a single working provider skipped compaction (`fallback="none_available"`) and
  the session kept growing.
- Quota, usage or budget exhaustion, rate limits, authentication failures and
  "no available … accounts" pool exhaustion still move to another provider only.
- `OPENAGENT_COMPACTION_FALLBACK_MODEL` is honoured whatever its provider.
- At most two fallback calls, never repeating a model; each attempt is logged as
  `runtime.compaction.summary_fallback` with `reason` and `fallback_model`, and a
  final failure reports `attempts`. See `docs/compaction-summary-fallback.md`.
