# Core beta148

Terminal stream failures retain their original provider category. A failed,
cancelled or already committed run no longer starts nonstream generation as a
second attempt. Output and executed tools do not authorize replay.

Automatic model cooldowns retain only an allowlisted public failure code,
scoped to the runtime instance. Repeated requests can explain authentication,
credit or quota failures while skipping the cooling connection; eligible
alternative models remain available. Provider diagnostics and exception objects
are not stored in this health state.

Real SDK/HTTP/SQLite regressions cover single-model catalogs, disabled backups,
exhausted backups and repeated requests, alongside cancellation, partial output
and tool boundaries. These local fixtures do not certify provider availability
or a deployed messaging channel. Installed-cohort qualification, publication
and host acceptance remain separate gates.

See [provider failure messages](../provider-failure-messages.md) and
[automatic catalog recovery](../provider-accounts-and-backups.md).
