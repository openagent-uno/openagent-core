# Core 1.1.0 beta125

An authorized operation cancellation now finishes stopping its local execution
segment even if the requesting caller disconnects after the logical stop is
persisted. The logical cursor and current segment's cancellation intent are
written atomically. The existing SQLite cancellation writer is shared by both
paths; ordinary runtime cancellation retains its contract.

This supersedes beta124 for hosts adopting durable operations. A public
regression reproduces the disconnect between logical and physical cancellation,
verifies the persisted intent before the request finishes, and checks that both
logical and physical runs finish cancelled. Eighty focused runtime, gateway,
SDK, operation, streaming and SQLite tests plus ten subtests pass.

The kernel, SQLite adapter, gateway and Python SDK are `1.1.0b125`. The official
release workflow qualifies the exact tagged clean cohort and native permission
contracts on Linux, macOS and Windows before immutable publication. Existing
tags and assets are preserved. Provider-side cancellation and live consumer
acceptance remain separate domain responsibilities; no external job is assumed
cancelled solely because its local execution segment stopped.
