# Core 1.1.0 beta90

Changing one MCP source no longer disturbs the others, and the answer an agent
gets when it changes one is the real outcome.

- `MCPPool.reload()` restarts only sources whose resolved spec changed,
  appeared or disappeared (plus dormant ones). Unchanged sources keep their
  connection and toolkit, so a running turn keeps their tools: before, adding
  one source replaced every source and revoked the running turn's references,
  for example the shell of the agent's own computer.
- MCP registry writes (`upsert_mcp`, `set_mcp_enabled`, `delete_mcp`) use a
  dedicated short transaction; `upsert_mcp` returns the committed row. A
  COMMIT on the shared connection failed with "SQL statements in progress"
  while a sibling held an unfinished `INSERT ... RETURNING`, and the pending
  row was committed anyway, so callers reported a failed install that had
  succeeded.
- `mcp-manager` add, update, enable, disable and remove answers carry
  `"availability": "next_turn"` with a note: a run keeps the capability
  snapshot it was admitted with, so a new source is discoverable from the next
  turn.

See `docs/mcp-catalog-changes.md`.
