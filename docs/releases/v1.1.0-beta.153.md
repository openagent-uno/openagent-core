# Embedding release 1.1.0-beta.153

A host can run multiple workers against PostgreSQL, use a SQL document vault per authorized memory space, and stream session attachments to private object storage. SQLite remains available for a standalone worker. The session and memory catalogs resolve the caller's current grants on each page. [Runtime and storage](../postgres-runtime.md) · [Memory access](../memory-access.md) · [Import and restore](../vault-history.md)

Workers retain ordered session turns, use bounded admission, and resume durable operations after a restart. A run, delegated child or maintenance task that reads a note inherits access requirements for that revision. Dream can review explicitly granted activity and produce a proposal for its authorized audience. Model history can continue with independent messages after a note is forgotten.

An embedding host can attach scoped task computers backed by private Linux VMs. An interactive user can list desktop targets and request screenshots or input under separate grants. The broker checks the exact lease and target before dispatching. A project checkpoint records the original revision and a reviewable Git patch. [Computer host contracts](../remote-capabilities.md)

The release includes Python wheels and the installable JavaScript/TypeScript SDK archive. Both SDKs expose the final answer, its originating segment, personal catalogs and asynchronous replay iterators. The qualification receipt identifies the archive and its SHA-256.
