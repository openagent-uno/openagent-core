# Core 1.1.0 beta127

Two reports that named the wrong cause now name the right one.

- **Image generation says why the provider refused.** `generate_image_bytes`
  raises `ImageGenerationError` with the HTTP `status`, the provider's own
  error type or code (`kind`) and its message, instead of a bare
  "429 Too Many Requests for url …". The `media-gen` tool returns
  `{ok: false, reason, status, error_type}`. A subscription service that
  answers 429 because every account's sign-in has ended is no longer reported
  as an exhausted quota. See [image generation](../image-generation.md).
- **A run answered by a backup model is labelled with the backup.** The run
  envelope names the model the run started with; when that model failed and a
  backup answered, `session_runs.model`, the rebuilt journal and
  `SessionInspection.live_runs` named the model that had failed. They now use
  the run's per-model usage: the model that wrote the most output answered
  (`answering_model`). Runs recorded before this release keep their stored
  label. See [session history](../session-history.md).

Public regressions cover the provider error shapes (typed error, `detail`,
plain string, unreadable body, over-long message), the tool result, and the
three places that report a run's model.
