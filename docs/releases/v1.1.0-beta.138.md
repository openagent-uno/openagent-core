# Core beta138 — nullable compatibility metadata keeps history available

Runtime-owned sessions with legacy metadata saved as JSON `null`, arrays or
scalars no longer fail reconciliation while checking for an explicit rename.
The title bridge uses the shared bounded JSON decoder and accepts only objects;
double-encoded object titles retain the legacy reader's compatibility behavior.

The correction preserves canonical authorship, authorization, run records and
transcript data. Failed pending changes can retry normally after a host adopts
the qualified package; no host-specific database repair is required.

The regression reproduces the blocking error before the fix and checks pending
journal processing, readiness coverage, unchanged owner/title for absent rename
metadata, and an explicit double-encoded rename. Installed-package and remote
publication evidence are recorded separately from source checks.

Source qualification: nine targeted regressions pass, including five failures
reproduced before the correction. The full public suite passes 1,270 tests,
with two skips and 188 subtests, in the qualified dependency environment.
The 23 prompt tests also pass; together these cover 1,293 tests plus 188
subtests. The targeted nine tests were repeated after the version update.
