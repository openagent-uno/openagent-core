# Core 1.1.0 beta126

A host can opt an existing legacy resume into durable operation handoff using
only its operation name and source run ID:

```python
OperationHandoff(name, resume_run_id=source_run_id)
```

Core resolves the canonical accepted inputs and original checkpoint origin
through its existing read-only ancestry validator before grant capture. It
checks the full chain's authority, definition version and input digest. Explicit
inputs remain supported and must match. The consumer selects the operation and
authorizes delegation; it does not copy runtime traversal or checkpoint logic.

Public tests cover a source-only handoff after multiple legacy segments, the
canonical grant digest, one existing external receipt without a new submission,
restart before the new checkpoint, competing legacy resumes and changed-input
or identity rejection. Eighty-one focused runtime, operation, gateway, SDK,
streaming and SQLite tests plus ten subtests pass.

The kernel, SQLite adapter, gateway and Python SDK are `1.1.0b126`. The official
release workflow qualifies the exact tagged clean cohort and all-platform
native permission contracts before immutable publication. Live provider and
consumer acceptance remain separate.
