# Core 1.1.0 beta112

Provider accounts and backup models follow what the provider says.

- Credential pools (`metadata.accounts`) cool an account down for the
  provider's standard `Retry-After` (seconds, HTTP date or `retry-after-ms`,
  bounded to 1 s … 31 days) instead of a fixed hour, so a usage window that
  resets in days is not retried hourly and a short burst limit does not idle an
  account for an hour. `retry_after_seconds()` reads it from the original HTTP
  error behind a `ModelProviderError`.
- A rejected credential (401/403) now moves the request to the next account of
  the pool, in full responses and in streams before the first event; the
  account is retired until the provider configuration changes.
- Provider rows returned by the management API no longer expose
  `metadata.accounts[*].api_key`; each entry shows `api_key_display`.
- Catalog backup models: an enabled language model whose metadata has a
  non-negative integer `fallback_priority` joins the rate-limit and error
  fallback chains, lowest first, after configured refs. The chain follows the
  live catalog without a restart.

See [Provider accounts and backup models](../provider-accounts-and-backups.md).
