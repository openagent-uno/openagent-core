# Core beta142 — exact-account quota telemetry

Claude quota observations from both native transports are captured on successful
and limited responses, including streaming. Request-local observers preserve
account identity under concurrent calls. Only allowlisted telemetry is stored;
provider headers and credentials are not exposed to consumers.

The public `refresh_usage` operation lets an authorized host monitor make a
minimal probe through an exact account's ordinary native admission lane.
Results identify stale/missing observations instead of inventing zero usage.
Consumer quota and fallback policy can keep using its existing thresholds
without reading OAuth credentials or depending on a custody listener.
Optional telemetry storage failure does not turn a valid reply into an error.
Storage remains compatible with beta141, whose stream ownership correction and
offline localization contract are retained.
