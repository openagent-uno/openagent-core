# Core 1.1.0 beta120

A goal a runtime restart interrupted starts again, or says why it stopped.

- New `session_goal.resume_after_restart(db, authority=..., submit=...)`, for
  a host to call once after it started. For every active goal whose latest
  run a restart interrupted: with the owner's durable delegation
  (`authority(session_id)` returns its `ExecutionContext`) the goal uses one
  continuation and a new run is admitted, told that the earlier turn was
  interrupted and to check the state before repeating anything. Without a
  delegation the goal pauses with the reason. When the interrupted run was
  already such a resume, the goal pauses instead of looping. Before this, the
  goal stayed "active" and nothing worked on it until someone wrote.
- New `GoalStore.interrupted_by_restart()` and `session_goal.restart_prompt`.
- New optional `ChatCommandHost.goal_changed(session)`: called in the verified
  scope of the person who changed a goal with `/goal`, so a host can capture
  or withdraw the delegation.
