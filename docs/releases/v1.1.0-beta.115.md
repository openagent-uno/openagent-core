# Core 1.1.0 beta115

A backup model that never answers no longer holds the turn.

- Each streaming backup in a fallback chain now has a bounded wait for its
  first provider output: `OPENAGENT_FALLBACK_FIRST_OUTPUT_TIMEOUT_S`, default
  120 seconds, `0` disables it. Past the bound, the backup's stream is closed,
  the backup enters the fallback breaker like any other failure, and the next
  backup is tried. When none answers, the turn reports the original failure.
  Before this change, a backup that accepted the connection and never
  answered (an offline machine behind a VPN, a stopped local server) kept the
  turn waiting for the provider SDK's read timeout and its retries. The user
  saw a reply that kept loading.
- The local markers that come before the request (request started, compaction)
  restart the wait. Once output has started, the stream is never cut. The
  primary model and non-streaming calls are unchanged.
